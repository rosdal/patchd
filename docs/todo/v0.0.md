# Patchd Code — v0.0 Development TODO

Oct 19, 2026 · @Mark

## Goal and definition of done

This TODO takes Patchd from an empty folder (v0.0) to the v0.1 repo foundation in about 1–2 weeks: a monorepo where pnpm runs every task, Go and TypeScript build and test in CI, and `patchd version` works. No analysis code yet, apart from one time-boxed spike.

**Done means all of these are true:**

- [ ] A fresh clone followed by `pnpm install && pnpm build && pnpm test && pnpm lint` succeeds on Linux and macOS.
- [ ] `./bin/patchd version` prints version, commit and build date.
- [ ] CI is green on `main` and required for merging.
- [ ] The typescript-go spike type-checks one real TypeScript project from Go, and the result is written up as an ADR.
- [ ] Tag `v0.1.0` exists.

**Conventions used below:** commands run from the repo root unless stated; `$` lines are shell commands; versions marked "pin" get an exact version written into a file so every machine and CI use the same one.

**Notes**

- pnpm 10 doesn't run dependencies' install scripts by default. If a package needs one (for example `esbuild`), approve it with `pnpm approve-builds`; the approval is saved in the workspace config. Keep that list short: it's part of Patchd's own supply-chain security.

`tools/scripts/build-go.mjs`

```js
import { execSync } from "node:child_process";

const sh = (cmd) => execSync(cmd, { encoding: "utf8" }).trim();
const version = sh("git describe --tags --always --dirty") || "v0.0.0-dev";
const commit = sh("git rev-parse --short HEAD");
const date = new Date().toISOString();
const pkg = "github.com/patchd/patchd/internal/buildinfo";
const ldflags = [
  `-X ${pkg}.Version=${version}`,
  `-X ${pkg}.Commit=${commit}`,
  `-X ${pkg}.Date=${date}`,
].join(" ");

execSync(`go build -trimpath -ldflags "${ldflags}" -o bin/patchd ./cmd/patchd`, {
  stdio: "inherit",
});
```

var errNotImplemented = errors.New("not implemented yet")

func newRootCmd() *cobra.Command {
	root := &cobra.Command{
		Use:           "patchd",
		Short:         "Patchd Code: find it, prove it, patch it",
		SilenceUsage:  true,
		SilenceErrors: true,
	}
	root.AddCommand(newVersionCmd())
	for _, name := range []string{"serve", "worker", "sandboxd", "scan", "review", "fix", "lsp", "mcp"} {
		root.AddCommand(stub(name))
	}
	return root
}

func stub(name string) *cobra.Command {
	return &cobra.Command{
		Use:   name,
		Short: name + " (not implemented yet)",
		RunE:  func(*cobra.Command, []string) error { return errNotImplemented },
	}
}
```

`cmd/patchd/version.go`

package main

import (
	"fmt"
	"runtime"

	"github.com/patchd/patchd/internal/buildinfo"

func newVersionCmd() *cobra.Command {

		Short: "Print version information",
		Run: func(cmd *cobra.Command, _ []string) {
			fmt.Fprintf(cmd.OutOrStdout(), "patchd %s (commit %s, built %s, %s/%s)\n",
				buildinfo.Version, buildinfo.Commit, buildinfo.Date, runtime.GOOS, runtime.GOARCH)
		},
	}
}

  push:
    branches: [main]
  pull_request:
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  build-test-lint:
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@<sha> # pin
        with:
          fetch-depth: 0 # git describe needs tags
      - uses: pnpm/action-setup@<sha> # pin; reads packageManager
      - uses: actions/setup-node@<sha> # pin
        with:
          node-version-file: .node-version
          cache: pnpm
      - uses: actions/setup-go@<sha> # pin
        with:
          go-version-file: go.mod
          cache: true
      - run: pnpm install --frozen-lockfile
      - run: go install mvdan.cc/gofumpt@latest
      - uses: golangci/golangci-lint-action@<sha> # pin; v2.x
        with:
          version: v2.x.x # pin exact
      - run: pnpm lint:ts
      - run: pnpm format:check
      - run: pnpm test
      - run: pnpm build
      - run: ./bin/patchd version
  commitlint:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<sha>
        with: { fetch-depth: 0 }
      - uses: pnpm/action-setup@<sha>
      - uses: actions/setup-node@<sha>
        with: { node-version-file: .node-version, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm commitlint --from ${{ github.event.pull_request.base.sha }} --to ${{ github.event.pull_request.head.sha }}
```

## Step 9 · typescript-go spike

The spike answers the riskiest question in the whole plan before any engine code is written: can Go code load a real TypeScript project and query the TypeScript 7 checker in-process? Time-box it to 3 days; the output is an ADR plus throwaway code on a branch, not production code.

**Background:** `typescript-go` keeps its compiler in `internal/` packages, which Go doesn't let other modules import directly. Oxc's tsgolint works around this; study exactly how before choosing an approach.

**Tasks**

- [ ] Read tsgolint's repository: how it pulls in typescript-go (submodule, vendoring or module replace), how its shim packages expose internals, and how it keeps up with new typescript-go commits.
- [ ] Pick a pinned typescript-go commit (the one matching a TypeScript 7.0.x release).
- [ ] On a branch `spike/tsgo`, set up the same mechanism under `engine/tsbridge/shim`.
- [ ] Write `cmd/spike-tsgo/main.go` that: loads a `tsconfig.json`, creates a program, gets the type checker, walks every file, and for every call expression prints `file:line callee-symbol → resolved declaration file:line` and the type of the first argument.
- [ ] Run it on 3 projects: a small one (a single Express app, for example NodeGoat), a medium one (a Next.js app), a large monorepo.
- [ ] Record for each: wall time, peak memory (`/usr/bin/time -v` on Linux, `-l` on macOS), number of files, any crashes or unsupported configs.
- [ ] Check 20 sampled call resolutions by hand against VS Code's "Go to definition".
- [ ] Try one upgrade: move the pin to a newer typescript-go commit and note how much of the shim breaks.

**Write-up: `docs/adr/0007-tsbridge-shim.md`**

- [ ] Chosen mechanism and why.
- [ ] Measured numbers (time, memory, accuracy of the 20 samples).
- [ ] Upgrade cost observed and the upgrade procedure.
- [ ] Fallback if the shim proves unworkable: run `@typescript/typescript6` (TS 6 API) in a Node sidecar, or wait for the TS 7.1 public API.
- [ ] Go / no-go decision for v0.2.
- [ ] Merge only the ADR and any reusable shim setup to `main`; keep the spike command on its branch.
