## Step 1 · Shim setup and upgrade procedure

The shim is the only place compiler internals enter Patchd, so it must be small, generated where possible, and easy to upgrade.

- [x] List the internal packages actually used (expected: AST, parser, binder, checker, compiler/program, tsoptions/tsconfig parsing, module resolution, virtual file system) in `engine/tsbridge/shim/README.md`, with why each is needed.
- [x] Generate shim files with a script rather than writing them by hand where the mechanism allows: `tools/scripts/gen-tsgo-shim.mjs`, run by `pnpm gen`.
- [x] `depguard` (from v0.1) confirms nothing outside `engine/tsbridge` imports the shim or typescript-go; add `engine/tsbridge/shim` to the denied list for other packages too.
- [x] Licence check: typescript-go is Apache-2.0; keep its `LICENSE` and `NOTICE` alongside the vendored copy and list it in `THIRD_PARTY_NOTICES.md`. — *Done: no vendored copy exists (module proxy), so `LICENSE` and `NOTICE` sit next to the shims in `engine/tsbridge/shim/`.*

**Upgrade procedure: `pnpm tsgo:update <commit>`**

1. Move the submodule (or replace directive) to the new commit and update `TSGO_VERSION`.
2. Regenerate the shim (`pnpm gen`).
3. Run `go build ./engine/...` and the tsbridge test suite.
4. Run the oracle comparison (Step 10) and the benchmarks (Step 11) on all reference repos.
5. Open a PR titled `chore(engine): bump typescript-go to <version>` with the before/after numbers in the description.

## Step 2 · tsbridge public API design

The public API is what every later version builds on, so design it first, review it as an ADR, and keep it small: only Patchd types cross the boundary, never compiler types.

- [x] Write `docs/adr/0008-tsbridge-api.md` with the API below and the rules for extending it.
- [x] Implement the types as Go interfaces or opaque handles in `engine/tsbridge/api.go`; implementations live in unexported files.
- [x] Every handle (`NodeID`, `SymbolID`, `TypeID`) is a small value type valid only for its `Program`, so later layers can store them cheaply in maps.

`engine/tsbridge/api.go` (sketch)

```go
package tsbridge

// Workspace is everything Patchd found under a repo root.
type Workspace struct {
	Root     string
	Projects []ProjectConfig // one per tsconfig/jsconfig (or synthesised)
	Warnings []Warning
}

// Discover finds projects under root without type-checking anything.
func Discover(ctx context.Context, root string, opts DiscoverOptions) (*Workspace, error)

// Load parses, binds and type-checks one project.
func Load(ctx context.Context, cfg ProjectConfig, opts LoadOptions) (*Program, error)

type Program struct{ /* unexported */ }

func (p *Program) Files() []FileID
func (p *Program) File(id FileID) *File
func (p *Program) Diagnostics() []Diagnostic
func (p *Program) Close() // frees checker memory

// Syntax
func (p *Program) Root(f FileID) NodeID
func (p *Program) Kind(n NodeID) Kind
func (p *Program) Children(n NodeID) []NodeID
func (p *Program) Parent(n NodeID) NodeID
func (p *Program) Range(n NodeID) Range
func (p *Program) NodeAt(f FileID, pos Pos) NodeID
func (p *Program) Walk(f FileID, visit func(NodeID) bool)

// Symbols and types
func (p *Program) SymbolOf(n NodeID) (SymbolID, bool)
func (p *Program) TypeOf(n NodeID) TypeID
func (p *Program) TypeString(t TypeID) string
func (p *Program) TypeFlags(t TypeID) TypeFlags // string, number, union, object, any, unknown…
func (p *Program) UnionMembers(t TypeID) []TypeID
func (p *Program) Properties(t TypeID) []SymbolID
func (p *Program) IsAssignable(from, to TypeID) bool
func (p *Program) Signature(call NodeID) (Signature, bool)

// Resolution
func (p *Program) Declarations(s SymbolID) []Location
func (p *Program) ResolveCall(call NodeID) (Callee, bool)
func (p *Program) ResolveAlias(s SymbolID) SymbolID
func (p *Program) QualifiedName(s SymbolID) string // e.g. "express.Request.query"
```

**API rules**

- No method returns or accepts a typescript-go type.
- No method panics on bad input; it returns a zero value plus `ok=false` or an error.
- Everything takes or derives a `context.Context` so long checks can be cancelled.
- `QualifiedName` is the stable string framework models will match on (v0.6), so define its format carefully: package name, then export path, then member path.

## Step 6 · Call and import resolution

Resolution tells later layers which real function a call reaches, which is what makes framework models ("`express.Response.redirect` is a sink") work.

- [x] `ResolveCall(call)`: for direct calls, method calls, `new` expressions, tagged templates and JSX components, return the callee symbol and its declaration(s).
- [x] Through aliases: `import { x as y }`, `export { x } from`, `export *`, `export default`, namespace imports, CommonJS `require` and `module.exports` in JS files.
- [x] Through types: a method call on an interface or abstract class returns all declarations the checker knows (the call graph narrows this in v0.5).
- [x] Declarations in `node_modules`: return the `.d.ts` location and the package name and version (from the nearest `package.json`), so findings can say "`pg` 8.11 `Client.query`".
- [x] `QualifiedName(symbol)`: stable format `<package>:<export path>.<member>` (for example `express:Response.redirect`, `node:child_process.exec`, `local:src/db.ts#runQuery`). Write the spec into ADR 0008.
- [x] Unresolvable calls (dynamic property names, `any`-typed receivers) return `ok=false` with a reason code; count them per repo, because they're where analysis is blind.

**Fixtures**

- [x] `engine/tsbridge/testdata/resolve/`: each fixture marks calls with `// resolves-to: express:Response.redirect` and the test checks `QualifiedName(ResolveCall(...))`.
- [x] Cover Express, `node:` built-ins, `pg`, Prisma client, default vs named imports, re-export barrels (`index.ts`), path aliases from `tsconfig.paths`.

## Step 7 · Robustness

Patchd will see thousands of messy repos; the rule is degrade, never die, and always say what was skipped.

| Situation | Behaviour | Warning code |
| --- | --- | --- |
| `node_modules` missing | Load anyway; unresolved packages become `unknown`; resolution reports `package-not-installed` | `TSB001` |
| Invalid JSON in a `tsconfig` | Skip that config; its files fall back to a synthesised project | `TSB002` |
| `extends` target not found | Use the config without the base, record it | `TSB003` |
| Syntax errors in a file | Keep the partial syntax tree; analyse what parsed | `TSB004` |
| Project over `MaxFiles` | Analyse the first N by priority (changed files first, then non-test source), report the rest | `TSB005` |
| Load or check exceeds `Timeout` | Cancel via context; return what's done | `TSB006` |
| Panic inside the compiler | Recover at the `tsbridge` boundary, mark the project failed, keep other projects | `TSB007` |
| Unsupported file types (`.vue`, `.svelte`, `.astro`) | Skip with a note (until framework support exists) | `TSB008` |

- [x] Implement each row with a fixture in `engine/tsbridge/testdata/broken/`.
- [x] `Warning` type: code, message, file, optional range; surfaced by `patchd debug project` and later in review summaries.
- [x] Every exported `tsbridge` function wraps compiler calls with `recover()` and converts panics into `TSB007` with a stack trace in debug logs.
- [x] Fuzz test (`go test -fuzz`) the loader with random `tsconfig` JSON and random file contents for at least 1 hour locally before release; no panics escape. — *Done: 1 hour, 13,527 runs, no panic escaped.*
- [x] Commit: `feat(engine): robust loading and warnings`. — *Done: `c8f2c75` with this subject.*

## Step 8 · Concurrency and memory

Monorepos have dozens of projects, so load them in parallel within a memory budget instead of all at once.

- [x] `LoadAll(ctx, workspace, opts)`: loads projects with a worker pool; default workers = number of CPU cores, configurable with `--jobs`. — *Done, with the default amended after measuring: a quarter of the CPU cores, because typescript-go already parses and checks each program on all cores and 16 jobs were slower than 4 on pnpm, juice-shop and create-t3-turbo (docs/engine/tsbridge.md#parallelism). `--jobs` overrides it.*
- [x] Memory budget (`--max-memory`, default 75% of available RAM): before starting a project, estimate its cost from file count and total size; wait if starting it would exceed the budget.
- [x] Shared, read-only caches across programs where the compiler allows it (library `.d.ts` files, parsed `node_modules` declarations), measured before and after.
- [x] `Program.Close()` releases checker memory; the analysis pipeline processes and closes one project before loading more when memory is tight.
- [x] Use typescript-go's own internal parallelism settings (its parallel parse and check) and measure how they interact with our worker pool; document the best defaults.
- [x] Race detector: the tsbridge test suite runs with `go test -race` in CI.
- [x] Expose metrics: projects loaded, files, time per phase (discover, parse, bind, check), peak heap.
- [x] Commit: `feat(engine): parallel loading with memory budget`. — *Done: `01bd561` with this subject.*
