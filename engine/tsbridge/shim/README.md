# typescript-go shims

typescript-go keeps its compiler in `internal/` packages, which Go refuses to import from another module. Each directory here is a small module named `github.com/microsoft/typescript-go/shim/<pkg>`; because that path sits under typescript-go's own module path, it may import `internal/<pkg>` and re-export it through type aliases, constants and `//go:linkname` declarations ([ADR 0007](../../../docs/adr/0007-tsbridge-shim.md)).

Only `engine/tsbridge` may import these modules or typescript-go; depguard enforces it in `pnpm lint`.

## Generated, not written

Every `shim.go` is generated by [`gen/`](gen/main.go) from the pinned typescript-go and committed exactly as generated. Run `pnpm gen` to regenerate. A package's `extra-shim.json` adds unexported functions, methods or struct fields to its shim; each private-field mirror needs a reason in review, because those break first on upgrades.

To move the pin, run `pnpm tsgo:update <commit>` and follow [docs/engine/tsgo-upgrades.md](../../../docs/engine/tsgo-upgrades.md).

## Packages and why each is needed

| Shim                                | What tsbridge uses it for                                                                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ast`                               | Syntax nodes, kinds, symbols and diagnostics: the syntax view, `NodeAt`, `Walk`, symbol and declaration lookups                                   |
| `bundled`                           | The `lib.*.d.ts` files embedded in the compiler, and the file system wrapper that serves them                                                     |
| `checker`                           | The type checker: `TypeOf`, `SymbolOf`, signatures, assignability, type printing, alias resolution                                                |
| `collections`                       | The ordered map the compiler stores `paths` in, so the removed `baseUrl` option can be translated to `paths`                                      |
| `compiler`                          | `Program` and `CompilerHost`: parsing every file, module resolution, binding (`BindSourceFiles`) and the checker pool                             |
| `core`                              | `CompilerOptions` and the enums in them (module kinds, resolution kinds, tristates)                                                               |
| `scanner`                           | Token positions: ranges that skip leading comments and whitespace                                                                                 |
| `tsoptions`                         | `tsconfig.json`/`jsconfig.json` parsing, `extends` (including from npm packages) and project references, so options mean what they mean to `tsgo` |
| `tspath`                            | Path normalisation and comparison the compiler expects                                                                                            |
| `vfs`, `vfs/cachedvfs`, `vfs/osvfs` | The file system interface; tsbridge wraps it read-only, with an in-memory overlay for synthesised configs                                         |

The parser, binder and module resolver are reached through `compiler` (`NewProgram`, `BindSourceFiles`) rather than shimmed directly.
